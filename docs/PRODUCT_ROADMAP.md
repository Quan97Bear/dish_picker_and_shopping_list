## 2. 当前代码基线

### 2.1 选菜页

- 40 道固定菜谱，恰好 5 道汤
- 分类、菜名搜索和五种忌口筛选
- 大卡片与响应式小卡片，可在本机记住选择
- 推荐、常吃、最快、分类和菜名五种稳定排序
- 最多选择 12 道菜
- 顶部菜单入口与滚动后的浮动菜篮子
- 点击菜品内容打开轻量翻转预览
- 预览显示主要食材、耗时、分类、口味和辣度

### 2.2 今日菜单

- 查看和移除已选菜
- 调整 1–8 人份
- 添加、修改和删除逐菜备注
- 填写最多 60 字的新菜建议
- 清空全部或继续选菜
- “生成菜单”打开分享界面

### 2.3 分享与做饭页

- 系统分享、复制链接和二维码
- URL 恢复菜品、人数、备注和新菜建议
- 做饭页显示菜单、完整菜谱和备注
- 用户点击后生成采购清单
- 采购清单支持人数缩放、兼容项合并、来源菜品、复制、折叠和本机勾选状态

### 2.4 手机视觉基线

- 360px 宽度不产生横向页面滚动
- 小卡片在 iPhone 14 为两列
- 页面、页首、吸顶工具栏和翻转预览使用同一个奶油色
- 网页内容位于 iOS 状态栏下方
- 翻转预览打开和关闭保持滚动位置
- Chromium 与 WebKit 都运行手机端回归测试

生产环境与当前本地候选版本的差异只在 `PROJECT_STATUS.md` 维护。

## 4. P1-A：发布当前手机体验

### 目标

将当前本地候选版本部署到 Cloudflare Pages，并确认 iPhone Safari 与微信中的真实表现。

### 验收

- iOS 顶部状态栏在页首、吸顶、预览打开和预览关闭时保持奶油色
- 网页内容不进入状态栏
- Safari 底部工具栏后方保持奶油色
- 翻转预览打开和关闭不移动页面
- 浮动菜篮子在安全区域内
- 360px、iPhone 14、横屏和较大字体无横向溢出或操作遮挡
- Chromium 与 WebKit 自动化通过
- 生产域名加载本次构建资源

## 5. P1-B：结果页与分享顺序

### 5.1 完成选菜

今日菜单的主动作改为“完成选菜”。

完成后进入结果页，不直接打开分享界面。结果页展示用户将实际使用或分享的内容。

### 5.2 结果页

- 顶部提供“采购清单 / 菜谱”切换
- 默认打开已经准备好的采购清单
- 采购清单整体和分类都可折叠
- 菜谱继续按道展开
- 逐菜备注和新菜建议保持可见
- URL 继续恢复相同菜单状态

### 5.3 分享

- 分享是结果页中的次级操作
- 点击分享后提供系统分享、复制链接和二维码
- 只提交新菜建议时，先显示建议预览
- 旧 `v=1` 分享链接继续可用

### 5.4 日历导出

结果页提供 `.ics` 导出设置：

- 日期默认今天
- 时间默认 18:30
- 持续时间默认 90 分钟
- 提醒默认提前 60 分钟，可关闭
- 事件包含菜单摘要、人数、备注和结果链接

第一版不把完整食材和做法写入日历。

### 验收

- 完成选菜首先进入结果页
- 采购清单默认可见
- 采购清单与菜谱切换可访问
- 分享不会抢先出现
- 新菜建议有独立预览
- `.ics` 可被 Apple Calendar 和至少一个其他日历客户端导入

## 6. P1.5：静态选择助手

P1.5 继续保持无账号、无后端、无在线 AI 服务。

### 6.1 一键家常搭配

按人数提供规则化组合：

| 人数 | 默认组合 |
| --- | --- |
| 1 人 | 1 荤/混合 + 1 素 |
| 2 人 | 1 荤 + 1 素 + 1 汤 |
| 3–4 人 | 2 荤 + 1 素 + 1 汤 |
| 5–6 人 | 2 荤 + 2 素 + 1 汤 |
| 7–8 人 | 3 荤 + 2 素 + 1 汤 |

要求：

- 遵守当前忌口
- 避免重复菜品、主要食材和相似口味
- 已有选择时只补齐，不删除、替换或重排
- 先显示组合预览，再允许换一组或加入菜单
- 候选不足时展示最接近的有效组合

### 6.2 静态食材指南

建立共用的静态食材数据：

- 稳定 ingredient key
- 标准名称和少量人工别名
- 是否属于常备调料
- 核心、辅助或可选角色
- 可选的短购买提示

购买提示不参与数量计算或合并。

### 6.3 已有食材找菜

用户通过搜索和常见食材 chips 选择现有食材，结果分为：

- 现在就能做
- 还差 1 样
- 还差 2 样

匹配只使用稳定 key 和人工别名，并继续遵守当前忌口。

### 验收

- 覆盖 1–8 人搭配
- 覆盖忌口、已有选择、候选不足和连续换组
- 覆盖食材别名、常备调料和缺少项计算
- 360px 下不挤压采购清单主要信息

## 7. P2：多人房间与跨设备

P2 只有在用户明确启动后才引入服务端能力。

### 最小多人版本

- 随机邀请房间，默认 24 小时过期
- 支持三人、四人及更多参与者
- 实时同步选择、取消、总数、在线状态和准备状态
- 同一道菜只显示一次，同时显示选择者
- 某人取消时保留其他人的选择
- 支持断线重连
- 完成前处理准备、拒绝、离线和明确强制确认
- 完成后生成稳定菜单快照

### 架构边界

```text
Cloudflare Pages
  → Worker API
  → 每个活跃房间一个 Durable Object
  → D1 保存账号资料与最终菜单
```

- 活跃选择保存在 Durable Object
- D1 不记录每次点击
- 完整菜谱继续来自静态 JSON
- 数据库只引用稳定 dish ID
- 保留旧静态分享 URL
- 上线前完成隐私、导出、删除、迁移和回滚设计

### 验收

- 多台真机可以同时点菜
- 同一道菜不会重复进入采购清单
- 断线重连后状态一致
- 离线成员不会被静默跳过
- 最终菜单只持久化一次

## 8. P3：个性化与家庭规划

在获得真实使用数据后再实施：

- 跨设备默认人数、偏好和菜单历史
- 基于常吃、速度和家庭接受度的可解释推荐
- 人工复核的清淡、高蛋白、蔬菜多标签
- 一周菜单、日期规划和采购提醒

健康信息只用于菜品比较，不作为医疗、过敏或疾病管理建议。

## 9. P4：自定义内容与商业化

先验证需求，再决定是否实施：

- 本机自定义菜谱与 JSON 导入导出
- 用户图片和云端存储
- 公共菜谱、审核、举报和删除
- 管理后台与运营菜单
- 图片、营养和外部买菜服务

本机版本优先于账号和公共内容版本。
