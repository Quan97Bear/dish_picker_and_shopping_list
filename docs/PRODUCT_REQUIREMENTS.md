# 家常菜单选择与采购清单 App — 产品需求文档

版本：1.6
日期：2026-07-25
状态：产品合同；生产偏差见 `PROJECT_STATUS.md`

本文定义跨版本保持稳定的用户承诺、数据合同和验收底线。它不记录任务状态、实现顺序或未来架构设计。

## 1. 产品定位

为个人、两个人或家庭提供一个手机优先的点菜网页：

- 选菜者只管挑喜欢的菜、填写忌口和逐菜备注。
- 选菜者通过“生成菜单”获得系统分享、复制链接和二维码。
- 做饭者打开链接后查看菜单、菜谱和采购清单。
- 核心选菜流程必须保持简单、快速，并可在没有账号时使用。

## 2. 成功标准

1. 普通用户能在 2 分钟内完成浏览、选菜和菜单检查。
2. 分享链接能跨设备恢复菜品、人数、备注和新菜建议。
3. 采购清单数量可追溯到具体菜品，不猜测单位换算。
4. 360px 宽手机无横向页面滚动，iPhone 14 完整可用。
5. 菜单数据可以轮换，同时保持旧分享链接兼容。

## 3. 用户角色

- **选菜者**：浏览、筛选、选择、备注和完成菜单。
- **做饭者**：查看菜单、菜谱、备注和采购清单。
- **维护者**：维护菜谱数据、来源、测试和部署。

多人共同点菜与账号用户属于未来范围，由 `PRODUCT_ROADMAP.md` 定义。

## 4. 运行菜单合同

### 4.1 强制约束

- `data/dishes.json` 与 `data/dish-index.json` 包含完全相同的 40 个稳定 ID。
- 恰好 5 道菜的 `category` 为 `soup`。
- 当前运行菜单不得包含茄子或鱼类菜品。
- 青椒和尖椒菜品允许保留。
- `data/dish-catalog.json` 只用于本地轮换，不得在运行时请求或打入生产数据。
- 不复用已发布 ID；改名或替换通过 `data/aliases.json` 兼容历史链接。

### 4.2 每道菜的数据

完整菜谱至少包含：

- 稳定 ID、菜名、分类、标签和预计耗时
- 基准份数、难度与忌口元数据
- 结构化食材：key、名称、数量、单位、采购分类、可选状态和 rounding
- 工具、步骤与提示
- 来源项目、路径、URL、许可证、获取日期和复核状态

来源保留在数据与维护记录中；用户界面不显示 GitHub/HowToCook 链接，运行时也不得读取 GitHub。

## 5. 选菜合同

- 用户可以按分类、菜名和支持的忌口规则筛选候选菜。
- 支持的忌口规则为青椒/尖椒、鱼、猪肉、鸡蛋和辣味。
- 忌口只影响候选展示。切换忌口不得删除已选菜、备注或选择顺序。
- 已选菜与忌口冲突时提醒用户，由用户决定是否移除。
- 普通忌口不宣传为过敏安全能力。
- 最多选择 12 道菜。
- 人数范围为 1–8，默认 2。
- 草稿可保存在当前浏览器。
- 用户能明确查看当前已选数量，并进入已选菜单。

## 6. 备注与新菜建议

- 每道已选菜可附加一条最多 80 字的备注。
- 备注可以添加、修改、删除，并在分享后对做饭者可见。
- 回车提交备注，Escape 取消编辑并恢复合理焦点。
- 删除一道菜不得影响其他菜的备注。
- 用户可以填写总长度最多 60 字的一道或多道新菜建议。
- 新菜建议可以在没有选择现有菜品时单独分享。
- 建议不会自动进入运行菜单，必须由维护者审核。

## 7. 分享状态合同

当前协议版本为 `v=1`。

```text
/?menu=tomato-egg,pepper-pork&p=2&v=1
```

参数：

- `menu`：去重并保持顺序的稳定菜品 ID，最多 12 个
- `p`：1–8 人份，非法值恢复为 2
- `notes`：以菜品 ID 为键的备注 JSON，每条最多 80 字
- `suggestion`：最多 60 字的新菜建议
- `v`：协议版本

解析规则：

- 没有 `menu` 参数时进入选菜模式。
- 未知或非法 ID 被安全忽略并向用户提示。
- aliases 可恢复已经发布的旧 ID。
- 未识别版本时尽量恢复并提示。
- URL 只保存状态，不保存完整菜谱。
- 链接持有者可以读取备注和建议，因此不得填写敏感信息。
- 系统分享不可用或失败时，必须提供复制链接和二维码。

## 8. 菜谱合同

- 做饭者可以看到菜单数量、人数、菜名、备注和新菜建议。
- 每道菜显示按人数缩放的食材、编号步骤、耗时、难度和提示。
- 菜谱可以逐道展开或收起。
- 全部 ID 无效且没有建议时显示可恢复的空状态。
- 来源信息不出现在用户菜谱 UI。

## 9. 采购清单合同

- 采购清单按目标人数缩放。
- 每项显示名称、数量、单位和对应菜名。
- 分类和整体均可展开或收起。
- 勾选状态保存在当前设备。
- 支持复制纯文本。

合并规则：

1. 仅在 ingredient key、unit、optional 均兼容时合并。
2. 不同单位不猜测换算。
3. `amount: null` 或“适量”项目去重但不数值求和。
4. 鸡蛋等离散单位使用数据中的 rounding 规则。
5. 合并后保留所有来源菜名。

## 10. 界面与无障碍合同

- 手机优先，360px 宽无横向页面滚动。
- 筛选区及其吸顶紧凑入口统一使用“忌口”作为标题。
- 关键操作使用语义控件、可见键盘焦点和清晰标签。
- 有效触控目标至少约 44×44 CSS px；视觉图形可以更小。
- 关闭、删除、编辑、加减和展开图标在自身盒子中光学居中。
- 固定与浮动入口适配 iOS safe area 和微信动态视口。
- 同一操作的顶部与浮动入口不能同时暴露给辅助技术。
- 候选区提供大卡片和小卡片两种明确模式；窄屏默认小卡片，宽屏默认大卡片，并记住用户选择。
- 小卡片使用响应式多列布局，单卡保持约 160px 最小宽度；iPhone 14 为两列，可用宽度足够时再自动增加列数。
- 点击菜品内容从原卡片位置翻转并放大显示轻量预览；关闭时反向缩回，加入按钮保持独立。
- 轻量预览显示分类、耗时、主要食材、口味和辣度，并使用模态语义、焦点循环、Escape 与背景关闭。
- 页首、滚动、吸顶、打开预览和关闭预览时，iOS 顶部状态栏、网页基础画布、吸顶工具栏和 Safari 底部工具栏后方视觉上保持同一个奶油色。
- 网页内容始终位于 iOS 状态栏下方；吸顶只改变控件位置和布局，不改变基础颜色。
- 轻量预览使用覆盖整个网页可视区域的奶油色背景，打开和关闭时保持原滚动位置。
- 浏览器界面的最终颜色与安全区域必须用真机 iPhone Safari 验收；自动化测试负责网页颜色、viewport、吸顶和预览状态。
- 今日候选提供推荐、常吃、最快、分类和菜名五种稳定排序；选择保存在本机，加入或移除菜品不得让当前列表跳位。
- 菜名排序使用运行菜单维护的拼音键；常吃排序使用本机历史，当前操作只影响后续浏览。
- 切换显示方式、选择菜品或跨越列数临界宽度时不得造成卡片跳动、页面闪烁或横向滚动。
- 尊重 `prefers-reduced-motion`、`prefers-reduced-transparency` 和高对比模式。
- 动效短、连续、可中断，不使用妨碍选菜的装饰动画。
- 菜品默认使用类别 emoji，除非用户明确选择其他图片系统。

## 11. 当前技术边界

P0/P1 使用：

- Vite
- 原生 HTML、CSS、JavaScript ES Modules
- Vitest 与 Playwright
- 本地打包的二维码库
- 静态 JSON 与 URL 状态

P0/P1 不加入账号、数据库、服务端函数、在线 GitHub 读取、付费 API、分析或广告。

未来多人和跨设备能力不得破坏无账号使用方式和旧静态分享链接；具体架构属于路线图，不在本文重复。

## 12. 验收底线

自动检查覆盖：

- 菜品数量、ID 一致性、5 道汤、禁用食材和来源字段
- URL 空值、重复、alias、非法 ID、人数、备注、建议和版本
- 采购合并、不同单位、可选项、适量与整数舍入
- 选菜、备注、人数、分享恢复、菜谱和采购清单关键流程
- 忌口不删除已选菜或备注

每次相关发布必须：

- 通过 `npm run validate:data`
- 通过 `npm test`
- 通过 `npm run build`
- 在可用时通过相关 Playwright 流程
- 在约 360px 和 iPhone 14 检查重叠、裁切、焦点和横向溢出
- 对浮动控件检查微信式视口与 safe area
- 确认 `dist/` 不包含指导文档、skills、测试、维护数据或 source map
- 确认生产域名加载本次构建资源

## 13. 部署合同

- 生产平台：Cloudflare Pages
- 项目：`dish-picker`
- 域名：https://dish-picker.pages.dev
- Build command：`npm run build`
- Output directory：`dist`
- P0/P1 不启用 Pages Functions

只允许部署 `dist/`。更换平台或启用后端必须由用户明确决定。
